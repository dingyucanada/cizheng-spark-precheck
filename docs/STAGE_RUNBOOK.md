# 瓷证 · 大会现场演示手册

目标是展示一个完整产品：器物持有人提交照片，Spark 在现场完成观察、资料核查及报告生成，最后带走一页意见。模型安装和设备调试在上台前完成。

## 两个界面，各自负责什么

| 入口 | 使用者 | 内容 |
|---|---|---|
| `http://127.0.0.1:8790/?new=1` | 收藏者、现场观众 | 添加照片 → 确认预检 → 分析核查 → 一页报告；我的器物；全屏展示 |
| `http://127.0.0.1:8790/operator` | 操作员，上台前使用 | 模型状态、中文字体、参考资料、原图完整性、真实排练、备用报告；不出现在用户导航 |

准备台只允许本机或 SSH 隧道访问，仍遵守配置的访问口令。它是本机维护入口，不是具有独立管理员角色的多租户后台。

用户界面没有预设评分卡片、模型选择或安装按钮。开始预检必须实际调用视觉模型；设备不可用时保留照片并明确提示。打开已有报告标为“已保存报告”，不能用旧结果冒充现场计算。

## 提前一天：完成安装和照片准备

1. 在实体 Spark 按 START_HERE.md 安装本地模型、容器和应用。首次下载、字体安装、驱动排错均在此时完成。
2. 准备一件已获授权的器物，建议3张照片：整体、底足、关注细节。文件存在 Spark 桌面一个清楚命名的文件夹中；另备U盘。当前主界面是照片上传，不宣称已经接通相机直播采集。
3. 如使用项目随包公开馆藏照片，在准备台下载照片包，解压后每个文件夹只对应一件器物。照片来源选择“公开馆藏”，口述也是公开馆藏图像；不能称为现场新拍。
4. 使用设备内已缓存资料，关闭本次预检的公开联网查询，避免把现场成功依赖于会场网络。需要联网检索的扩展能力可以另行介绍。
5. 按完整用户流程实际运行至少两次，检查观察位置、引用原文、评分理由及一页PDF。按实际耗时安排讲述长度，不事先承诺固定秒数或固定分数。结果不合适应修复提示、证据或流程，再重跑。

## 上台前30分钟：预热和整条流程检查

在项目目录执行：

```bash
bash scripts/prepare-stage.sh
```

它会启动已安装的应用和模型，真实读取双图，再强制生成一份新的视觉报告。之后检查：

- 服务返回了配置的模型名称；
- 中文字体可用，公开照片原文件指纹一致，本地资料已载入；
- **本次应用启动后**有一次真实双图以上的视觉调用成功，并形成完整报告；
- 报告PDF和输入原图指纹一致；
- 当前没有排队或执行中的任务。

只做健康检查、打开资料体验、使用测试替身，都不能满足完整排练条件。检测记录在 `runtime/stage/readiness.json`；备用PDF及排练照片包也保存在 `runtime/stage/`。若修改 CZ_DATA_DIR，则使用该目录下的 stage 文件夹。

准备台显示检查通过后，还要人工确认：电源稳定、设备散热、显示器和大屏连接正常、浏览器缩放100%、全屏字大小可读、通知免打扰已启用、照片文件夹容易选择。用现场设备计时一遍，给提问和等待留余量。不要在临上台时升级驱动、换模型或下载新权重。

## 上台前5分钟：固定展示起点

1. 将真实预热报告下载为PDF，提前在本机PDF阅读器打开，作为明确的备用材料。
2. 切换至 `/?new=1`，页面停在“添加照片”，确认没有前一份报告遮住流程。
3. 关闭准备台和终端的投屏窗口，打开“全屏展示”。
4. 让 Spark 放在观众可见位置；说明照片和推理发生在这台设备上。已准备好的公开图片应说明来源。

## 台上的操作顺序

| 操作 | 建议讲述 | 观众看到 |
|---|---|---|
| 选择同一器物的3张照片 | “送到专业机构之前，我先把整体、底足和关注位置拍清楚。” | 真实照片缩略图，不显示预设结论 |
| 选择视角，填写名称及问题 | “我想了解的是口沿是否有修补，以及需要补充哪些细节。” | 简短自然的表单 |
| 点击下一步确认 | “先核对照片属于同一件器物，再开始预检。” | 整体大图、局部缩略图、预检问题 |
| 点击开始本次预检 | “这台 Spark 正在读取图像，再核对本地资料和判断理由。” | 来自后台的真实阶段进度，无虚构倒计时 |
| 阅读报告 | “这里先给意见和送检关注评分。更重要的是每条理由具体对应哪张照片、什么依据。” | 一页报告和实际照片 |
| 展开依据，下载PDF | “可以带着这些具体问题咨询专业机构，原图和证据也保留下来了。” | 照片观察、原始引用、PDF |

主界面每次点击“开始本次预检”都明确请求新的本地分析。打开“我的器物”只查看保存结果，不重复创建器物，也不在后台偷偷重算。

## 现场异常时怎么处理

- **页面意外刷新**：点击顶部继续提示，恢复同一任务；不要反复提交新任务。
- **浏览器连接中断**：点击“重新连接任务”；后台可能仍在处理，不立即重复推理。
- **模型超时或失败**：照片保留，可重试。若时间不足，明确说“这里展示刚才排练时生成的报告”，打开“我的器物”中的已有报告或备用PDF。
- **大屏浏览器打不开**：切换提前打开的本机PDF，明确这是已保存报告。准备台保留故障记录，演示后排查。
- **评分和预想不同**：围绕本次实际理由讲解；不修改分数迎合演示，不把未发现疑点解释为真品。

代码和准备流程能降低失败概率，不能保证任何现场都不出故障。以真实实机彩排和明确的备用路径保障展示完整性。
